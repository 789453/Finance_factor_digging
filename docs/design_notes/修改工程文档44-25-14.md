# Finance\_factor\_digging 因子挖掘质量提升工程文档 v1

## 0. 目标、范围与核心判断

本轮修改目标不是继续做“能跑通”的工程扩展，而是直接提升“实际挖出来的因子质量”。当前项目已经比 AlphaSAGE 原始仓库多了大量工程化模块，包括 `datahub`、`alphagen_generic`、`mining`、`evaluation`、`progress`、`integration`、`preprocess_features_v2.py`、`train_gfn_v2.py` 等，项目结构已经从 AlphaSAGE 的研究脚本，扩展成更接近生产研究系统的框架。你的仓库 `src` 下确实已经包含这些模块。([GitHub](https://github.com/789453/Finance_factor_digging/tree/feature/non-data-progress-fourth-425/src "Finance_factor_digging/src at feature/non-data-progress-fourth-425 · 789453/Finance_factor_digging · GitHub"))

但是，因子质量差的根因主要集中在五个层面：

1. **表达式生成阶段没有足够强的结构硬约束**：常数、单变量、浅层表达式、等价恒等式能出生。
2. **入池逻辑过度依赖 abs(IC) 与 value correlation novelty**：没有 train/valid/test 分离、没有 RankIC、ICIR、rolling、coverage、TopK、稳定性等。
3. **新颖性度量太单薄**：`ic_mut` 只是因子值互相关，不等于表达式语义新颖。
4. **搜索空间没有鼓励“有效复杂”**：只是放开算子，不等于能生成复杂有效因子；还需要复杂度奖励、复杂度下限、无效复杂惩罚。
5. **数据域未按 stock\_moneyflow / cffex\_fut\_daily\_selected / cffex\_opt\_daily 做 domain-specific 适配**：不同数据源应该有不同目标、字段族、算子约束、窗口、TopK 逻辑和评估切面。

AlphaSAGE 原论文/仓库的核心主张是用结构感知编码器、GFlowNet 和 dense reward 来缓解 reward sparsity、序列表达不足和 mode collapse，并生成“diverse、novel、predictive”的 alpha portfolio。([arXiv](https://arxiv.org/abs/2509.25055 "\[2509.25055] AlphaSAGE: Structure-Aware Alpha Mining via GFlowNets for Robust Exploration")) 但这类方法是否能在你的数据上有效，取决于 reward 和 rejection 是否把“研究价值”定义清楚。你当前版本的核心短板就在这里。

```
train_rank_ic / valid_rank_ic / test_rank_ic
```

### 1.2 `src/alpha_gfn/alpha_pool_v2.py`：入池逻辑是质量瓶颈

当前 `AlphaPoolGFN.try_new_expr()` 大体逻辑是：

```
value = self._normalize_by_day(expr.evaluate(self.data))
ic_ret, ic_mut = self._calc_ics(value, ic_mut_threshold=0.99)
ic_ret = np.abs(ic_ret)
ic_mut = np.abs(ic_mut)

根据 entry_strategy 判断是否入池

nov_score = 1 - np.max(ic_mut)

```

这个逻辑的问题非常明确。`try_new_expr()` 会对 `ic_ret` 和 `ic_mut` 都取绝对值，然后按 `ic_ranking`、`diversity_aware`、`adaptive` 等策略入池；新颖性 `nov_score` 由 `1 - max(abs(ic_mut))` 得到。([GitHub](https://raw.githubusercontent.com/789453/Finance_factor_digging/feature/non-data-progress-fourth-425/src/alpha_gfn/alpha_pool_v2.py "raw.githubusercontent.com"))

这里至少有六个问题。

第一，**IC 取绝对值过早**。\
如果一个因子在 train 上 IC 为正，在 valid 上 IC 为负，你现在的 pool 可能仍然因为 `abs(IC)` 接收它。金融因子的方向稳定性是重要信号，不能只保留绝对值。

第二，**`ic_mut_threshold`** **参数在** **`_calc_ics(value, ic_mut_threshold=0.99)`** **中被硬编码为 0.99**。\
虽然入池策略后面会用 `self.ic_mut_threshold`，但是 `_calc_ics` 的参数名会造成混乱，而且传入 0.99 没有必要。建议彻底取消 `_calc_ics` 的 `ic_mut_threshold` 参数，只返回原始互相关数组，阈值判断统一在 policy 里做。

第三，**新颖性只来自因子值相关性**。\
两个表达式语义上几乎一样，但因为 NaN、窗口、coverage、截面分布差异，value correlation 可能没到阈值；反过来，一个完全无意义的复杂表达式，只要和池子不相关，也会得到很高 novelty。

第四，**adaptive threshold 方向疑似错误**。\
当前 `_update_adaptive_thresholds()` 中，当 `mean_ic > current_ic_threshold` 时，用类似：

```
self.current_ic_threshold = min(
    self.current_ic_threshold * self.adaptive_threshold_decay,
    mean_ic - 0.5 * std_ic
)

```

如果 `adaptive_threshold_decay < 1`，这个逻辑很可能不是提高门槛，而是把门槛往低处压。该方法确实使用 `min(...)` 和 `adaptive_threshold_decay` 组合更新当前 IC threshold。([GitHub](https://raw.githubusercontent.com/789453/Finance_factor_digging/feature/non-data-progress-fourth-425/src/alpha_gfn/alpha_pool_v2.py "raw.githubusercontent.com"))

第五，**diversity-aware 入池和替换规则不一致**。\
`_should_add_diversity_aware()` 在 pool 满时计算 `new_combined_score = ic_ret + diversity_weight * diversity_score`，但 `_add_factor()` 在 pool 满时仍然替换 `single_ics` 最低的因子，而不是 combined score 最低的因子。当前 `_add_factor()` 的注释也写着“池已满，替换最差的（基于 IC）”。([GitHub](https://raw.githubusercontent.com/789453/Finance_factor_digging/feature/non-data-progress-fourth-425/src/alpha_gfn/alpha_pool_v2.py "raw.githubusercontent.com"))\
这会造成策略不一致：用综合分数批准新因子，却用单一 IC 删除旧因子。

第六，**没有表达式质量硬拒绝**。\
`try_new_expr()` 里没有先调用类似：

```
quality = expression_quality.validate(expr)
if not quality.accept:
    return 0.0, 0.0

```

导致常数、裸变量、单算子、恒等式、未来函数、无效除法、重复表达式都可能进入评估环节，浪费训练预算。

### 1.3 `src/alpha_gfn/search_space_v2.py`：配置项存在，但没有转化成强约束

# Task B：新增表达式结构质量验证器

## 新增文件

```
src/alpha_gfn/expression_quality.py

```

## 目标

拒绝过于简单、无效、恒等、近似恒等、危险、未来函数、低覆盖表达式。这个模块必须在两个地方调用：

1. `GFNEnvCore.update_masks()`：防止过早 SEP。
2. `AlphaPoolGFN.try_new_expr()`：最终 hard reject，防止绕过环境直接入池。

## 数据结构

```

from typing import Dict, Any, List

@dataclass
class ExpressionQualityReport:
    accept: bool
    reason: str
    complexity: int
    depth: int
    n_features: int
    n_constants: int
    n_operators: int
    n_ts_operators: int
    n_binary_operators: int
    n_cross_feature_ops: int
    has_rank: bool
    has_ts_rank: bool
    has_pair_ts: bool
    canonical: str
    flags: Dict[str, Any]

```

## 核心接口

```
class ExpressionQualityValidator:
    def __init__(
        self,
        min_complexity: int = 4,
        min_depth: int = 2,

        min_features: int = 1,

        reject_raw_feature_only: bool = True,
        reject_single_ref: bool = True,
        reject_identity: bool = True,
        max_constant_ratio: float = 0.4,
        max_depth: int = 10,
    ):
        ...

    def analyze(self, expr) -> ExpressionQualityReport:
        ...

    def validate(self, expr) -> ExpressionQualityReport:
        ...

```

## 必须识别的拒绝模式

### 1. 常数表达式

拒绝：

```
1
0.5
2.0
Abs(1)
Rank(1)
TsMean(1, 20)

```

### 2. 裸变量表达式

拒绝：

```
close
volume
amount
open_interest
net_mf_amount

```

### 3. 单一简单时序表达式

初期可以拒绝：

```
Ref(close, 5)
TsMean(close, 5)
TsStd(close, 5)
TsRank(close, 5)

```

除非它是作为子表达式参与更复杂结构。

### 4. 恒等式 / 无意义表达式

拒绝：

```
x + 0
x - 0
x * 1
x / 1
x - x
x / x
x + x - 2*x
Rank(Rank(x))
TsMean(TsMean(x, 5), 5)  # 可降权，不一定硬拒

```

### 5. 过度常数化

拒绝：

```
Div(1, TsStd(close, 20))
Mul(2, Add(1, 0.5))

```

如果 `n_constants / max(1, n_features + n_operators) > max_constant_ratio`，直接拒绝或降权。

```
def expr_to_str(expr):

def count_ops(s):
```

## Hard Reject 顺序

在 `try_new_expr()` 开头按这个顺序：

```
1. expression quality reject
2. canonical duplicate reject
3. evaluate factor value
4. value sanity reject: nan/inf/coverage/zero-std
5. train metrics reject
6. valid metrics reject
7. pool correlation reject
8. semantic duplicate reject
9. composite score ranking
10. add or replace

```

注意顺序：embedding 放在 value sanity 之后，可以少算无效表达式的 embedding，节省时间。

## 不要只用 abs(IC)

建议指标中保存方向：

```
train_ic = metrics["train"]["ic_mean"]

test_ic = metrics["test"]["ic_mean"]  # 只报告，不参与入池

valid_ic_adj = direction * valid_ic
rank_ic_adj = direction * metrics["valid"]["rank_ic_mean"]
```

入池看：

```
if train_ic_adj < min_train_ic: reject
```

## Composite Score

```
    1.00 * valid_ic_adj
    + 0.50 * valid_rank_ic_adj
    + 0.20 * valid_ic_ir
    + 0.20 * valid_rank_ic_ir
    + 0.10 * topk_ls_sharpe_clipped
    + 0.10 * topk_ls_mean_clipped
```

```
turnover_penalty = max(0, topk_turnover - 0.8)
pool_corr_penalty = max(0, max_pool_corr - max_pool_corr_threshold)
```

# Task K：训练 reward 改造

当前 AlphaSAGE 原始 `reward()` 是：

```
reward = ic_reward + ssl_weight * ssl_reward + nov_weight * nov_reward

```

你的项目大体继承这个思路。原始代码确实在 `reward()` 里获取 `ic_reward, nov_reward, ssl_reward`，并组合成 `reward = ic_reward + ssl_weight * ssl_reward + nov_weight * nov_reward`。([GitHub](https://raw.githubusercontent.com/BerkinChen/AlphaSAGE/main/src/alpha_gfn/env/core.py "raw.githubusercontent.com"))

建议改成：

```
reward = (
    base_quality_reward
    + ic_weight * ic_component
    + rank_ic_weight * rank_ic_component
    + icir_weight * icir_component
    + novelty_weight * novelty_component
    + complexity_weight * complexity_component
    + topk_weight * topk_component
    - risk_penalty
)

```

但是为了效率，不要每个 reward 都跑完整 valid/test。训练阶段可分两级：

## 快速 reward

每个候选表达式：

```
train daily IC mean
train rank IC mean
coverage
complexity
pool value corr
canonical duplicate

```

## 入池 deep evaluation

只有候选通过快速 reward 后才计算：

```
valid IC
valid RankIC
ICIR
rolling IC
TopK
semantic embedding

```

这能控制耗时。

## Reward clipping

避免极端 IC 造成训练不稳定：

```
def clip_metric(x, lo=-0.1, hi=0.1):
    return max(lo, min(hi, x))

```

## 最小 reward

继续保留：

```
np.exp(-10)

```

但对 hard reject 建议直接返回极小值，不再加入 novelty：

```
if hard_reject:
    return min_reward

```

否则模型会因为“无效但新颖”得到正反馈。

# Task M：缓存与性能优化

## 当前缓存问题

`src/alpha_gfn/cache_manager.py` 有 `ExpressionValueCache`、`RewardCache` 和 `CacheManager`，但 `AlphaPoolGFN.try_new_expr()` 中调用的是：

```
cache_key = self.cache_key_builder.build_key(expr)

```

而 `CacheKeyBuilder` 公开代码里有 `expr_key`、`reward_key`、`data_hash`，没有看到 `build_key` 方法。([GitHub](https://raw.githubusercontent.com/789453/Finance_factor_digging/feature/non-data-progress-fourth-425/src/alpha_gfn/cache_manager.py "raw.githubusercontent.com"))\
这可能会导致启用 cache\_manager 后报错。

## 修改

在 `CacheKeyBuilder` 新增：

```
def build_key(self, expr, data_hash: str = "", config_hash: str = "") -> str:
    expr_str = str(expr)
    raw = f"{expr_str}|{data_hash}|{config_hash}"
    return hashlib.sha256(raw.encode()).hexdigest()[:16]

```

或者在 `AlphaPoolGFN` 改用：

```
cache_key = self.cache_key_builder.expr_key(str(expr), self.data_hash)

```

## 性能层级

1. canonical duplicate：O(字符串)，最便宜。
2. quality validate：O(表达式长度)，很便宜。
3. expr value cache：避免重复 evaluate。
4. quick metrics：只算 train daily IC/RankIC。
5. semantic embedding：比前面贵，放在 deep evaluation 后。
6. full valid/test report：最贵，只对入围因子算。

### 4.1 `AlphaPoolGFN.try_new_expr()` 重构

```
def try_new_expr(self, expr: Expression, embedding: Optional[Tensor] = None):
    self.stats["total_evaluations"] += 1

    # 1. expression quality
    q = self.quality_validator.validate(expr) if self.quality_validator else None
    if q is not None and not q.accept:
        self._reject(expr, reason=f"quality:{q.reason}", metrics={"complexity": q.complexity})
        return 0.0, 0.0

    # 2. canonical duplicate
    canonical = self.canonicalizer.canonicalize(expr)
    expr_hash = self.canonicalizer.hash(expr)
    if expr_hash in self.canonical_hashes:
        self._reject(expr, reason="duplicate:canonical")
        return 0.0, 0.0

    # 3. evaluate value
    try:
        value = self._get_or_eval_value(expr)
    except Exception as e:
        self._reject(expr, reason=f"eval_error:{type(e).__name__}")
        return 0.0, 0.0

    # 4. value sanity
    sanity = self.metrics_evaluator.value_sanity(value)
    if not sanity["ok"]:
        self._reject(expr, reason=f"value_sanity:{sanity['reason']}", metrics=sanity)
        return 0.0, 0.0

    # 5. quick train metrics
    train_metrics = self.metrics_evaluator.evaluate_value(value, split="train")
    direction = 1.0 if train_metrics["ic_mean"] >= 0 else -1.0
    train_ic_adj = direction * train_metrics["ic_mean"]

    if train_ic_adj < self.min_train_ic:
        self._reject(expr, reason="low_train_ic", metrics=train_metrics)
        return max(train_ic_adj, 0.0), 0.0

    # 6. valid metrics
    valid_metrics = self.metrics_evaluator.evaluate_expr(expr, split="valid", direction=direction)
    if valid_metrics["ic_adj"] < self.min_valid_ic:
        self._reject(expr, reason="low_valid_ic", metrics=valid_metrics)
        return max(train_ic_adj, 0.0), 0.0

    if valid_metrics["rank_ic_adj"] < self.min_rank_ic:
        self._reject(expr, reason="low_valid_rank_ic", metrics=valid_metrics)
        return max(train_ic_adj, 0.0), 0.0

    # 7. pool value novelty
    max_pool_corr = self._max_pool_corr(value)
    if max_pool_corr > self.ic_mut_threshold:
        self._reject(expr, reason="high_pool_corr", metrics={"max_pool_corr": max_pool_corr})
        return max(train_ic_adj, 0.0), 1.0 - max_pool_corr

    # 8. semantic novelty
    semantic_sim = 0.0
    semantic_vec = None
    if self.semantic_embedder is not None:
        semantic_vec = self.semantic_embedder.embed_one(canonical)
        semantic_sim = self._max_semantic_sim(semantic_vec)
        if semantic_sim > self.semantic_sim_threshold:
            self._reject(expr, reason="semantic_duplicate", metrics={"semantic_sim": semantic_sim})
            return max(train_ic_adj, 0.0), 1.0 - semantic_sim

    # 9. composite score
    novelty = self._combine_novelty(max_pool_corr, semantic_sim, q)
    score = self._composite_score(train_metrics, valid_metrics, novelty, q)

    # 10. add / replace
    added = self._add_or_replace(
        expr=expr,
        value=value,
        ic_ret=train_ic_adj,
        score=score,
        embedding=embedding,
        semantic_embedding=semantic_vec,
        quality=q,
        metrics={"train": train_metrics, "valid": valid_metrics},
        canonical=canonical,
        expr_hash=expr_hash,
    )

    reward = self._reward_from_score(score, novelty)
    return reward, novelty

```

### 4.2 `_add_or_replace()`

```
def _add_or_replace(self, expr, value, ic_ret, score, **meta):
    if self.size < self.capacity:
        idx = self.size
        self.size += 1
    else:
        idx = int(np.argmin(self.composite_scores[:self.capacity]))
        if score <= self.composite_scores[idx]:
            self._reject(expr, reason="score_not_better_than_pool_worst", metrics={"score": score})
            return False

        old_hash = self.canonical_hashes_by_slot[idx]
        if old_hash in self.canonical_hashes:
            self.canonical_hashes.remove(old_hash)

    self.exprs[idx] = expr if idx < len(self.exprs) else self.exprs.append(expr)
    self.values[idx] = value if idx < len(self.values) else self.values.append(value)
    self.single_ics[idx] = ic_ret
    self.composite_scores[idx] = score
    self.embeddings[idx] = meta.get("embedding")
    self.semantic_embeddings[idx] = meta.get("semantic_embedding")
    self.metric_records[idx] = meta.get("metrics")
    self.quality_records[idx] = meta.get("quality")
    self.canonical_exprs[idx] = meta.get("canonical")
    self.canonical_hashes_by_slot[idx] = meta.get("expr_hash")
    self.canonical_hashes.add(meta.get("expr_hash"))

    return True

```

## 6. 为什么这些修改会改善你现在的情况

你的系统现在不是“模型太弱”，而是“目标函数太容易被钻空子”。\
GFlowNet 会根据 reward 分布采样。如果常数、裸变量、浅层表达式能拿到 reward，模型就会学习它们；如果 novelty 只是 `1 - max(value_corr)`，模型就会生成“值上不太相关但语义上无意义”的表达式；如果 pool 只按 abs(IC) 入池，模型就会挖训练期偶然相关。

修改后，系统行为会变成：

```
常数 / 裸变量 / 恒等式：不能终止或直接 hard reject
浅层单算子表达式：低 complexity，被拒绝
重复表达式：canonical hash 拒绝
同义表达式：Ollama embedding 拒绝
训练期偶然 IC：valid IC / RankIC 拒绝
不稳定表达式：rolling / positive ratio 拒绝
复杂但无效表达式：valid score 不够，拒绝
复杂且有效表达式：complexity bonus + novelty bonus + TopK bonus

```

这才符合你想要的“复杂、新颖、有效”。

## 8. 我的最终建议

你应该先别急着判断“AlphaSAGE/GFlowNet 到底是不是比 GP/PySR 强”。PySR 这类成熟符号回归工具强调高性能、可配置、可解释表达式搜索，并且支持 operator complexity 这类约束。([GitHub](https://github.com/MilesCranmer/PySR?utm_source=chatgpt.com "PySR: High-Performance Symbolic Regression in Python and Julia")) 你的 GFlowNet 路线真正的优势不是“单个公式拟合一定更强”，而是能生成一个 **多样、低相关、结构复杂、可组合的因子池**。但要实现这个优势，必须把 pool 的入池目标从“abs(IC) 高”升级成“valid RankIC 稳定、TopK 有贡献、复杂度合理、语义不重复、池内低相关”。

你现在的项目工程基础是好的；真正卡住的是质量控制层。\
按这份文档改完后，你会看到三个直接变化：

```
1. 垃圾表达式数量明显下降；
2. 候选池规模可能短期变小，但 valid/test 指标更可信；
3. Ollama embedding 不再只是测试脚本，而会成为语义去重和效率统计的一部分。

```

最重要的一句话：**不要再让“能被表达式解析器接受”的东西自动进入因子评估；只有通过结构、语义、统计、稳定性四重验证的表达式，才配消耗 GFlowNet 的训练预算。**
