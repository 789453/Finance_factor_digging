# Finance Factor Digging 工程改造文档：先跑通框架，再扩展生成器

## 0. 改造目标

当前阶段的唯一目标不是做“顶级架构”，而是把项目压缩成一条可验证、可复用、可记录失败原因的主流程：

```
DatasetMeta / JobSpec
        ↓
DataHub / ParquetFeatureLoaderV2
        ↓
FactorGenerator: GFN / manual / llm / gp / pysr
        ↓
Expression Parser / Adapter
        ↓
Quality Filter
        ↓
Value Evaluation
        ↓
Metrics Evaluation: IC / RankIC / IR / Coverage / NaN
        ↓
Accept Pool + Rejection Log + Final Report

```

当前应遵守三个原则：

1. **生成器只生成候选表达式，不直接决定入池。**
2. **所有表达式必须记录，包括语法错误、结构不合格、计算报错、指标不达标。**
3. **尽量改现有文件，不新建复杂模块；真正要新增的只允许一个薄适配文件或测试配置，其他都落在现有** **`mining / alpha_gfn / alphagen_generic / evaluation`** **中。**

## Task 2：修复 target 对齐逻辑

### 涉及文件

```
src/mining/mine_factors.py
src/alphagen_generic/parquet_feature_loader_v2.py

```

### 当前问题

`build_alpha_context()` 里 target 是这样构造的：

```
price_col = target_cfg.get("price_column", "close").upper()
base = Feature(feature_enum[price_col])
horizon = int(target_cfg.get("label_days", job_spec.label_days))
target = Ref(base, -horizon) / base - 1

```

风险点：

1. `feature_enum[price_col]` 要求 enum 名一定是大写字段，例如 `CLOSE`。
2. 如果 registry 里字段带 layer 前缀或 domain 前缀，会 KeyError。
3. `valid_data` 在 `AlphaPoolGFN.try_new_expr()` 里使用 `self.valid_data.target if hasattr(self.valid_data, 'target') else self.target`，但 loader 当前并没有明确设置 `target`，因此 valid/test 可能使用 train target，存在日期长度和股票池错配风险。([GitHub](https://raw.githubusercontent.com/789453/Finance_factor_digging/feature/non-data-progress-fourth-425/src/alpha_gfn/alpha_pool_v2.py "raw.githubusercontent.com"))

### 修改方案

#### 1. 给 loader 绑定 target

在 `build_alpha_context()` 生成 target 后，立刻：

```
train_loader.target = target.evaluate(train_loader)
if valid_loader is not None:
    valid_loader.target = target.evaluate(valid_loader)
if test_loader is not None:
    test_loader.target = target.evaluate(test_loader)

```

但注意：`target` 是 `Expression`，`AlphaPoolGFN` 父类可能也需要 expression，而 evaluator 需要 tensor。建议分开命名：

```
target_expr = Ref(base, -horizon) / base - 1
train_target_tensor = target_expr.evaluate(train_loader)

train_loader.target = train_target_tensor
valid_loader.target = target_expr.evaluate(valid_loader)
test_loader.target = target_expr.evaluate(test_loader)

```

`AlphaPoolGFN` 初始化仍传 `target=target_expr`，如果父类内部会 evaluate，则不破坏原逻辑。若父类实际期待 tensor，则改为传 `train_loader.target`。这里必须通过测试确认。

#### 2. 封装 target 构造函数

在 `mine_factors.py` 中新增函数：

```
def build_target_expression(dataset_meta, job_spec, feature_enum):
    target_cfg = dataset_meta.target_config
    price_col = target_cfg.get("price_column", dataset_meta.columns.get("close", "close"))
    key = price_col.upper()

    if key not in feature_enum.__members__:
        raise KeyError(
            f"Target price column {key} not found in feature enum. "
            f"Available examples: {list(feature_enum.__members__.keys())[:20]}"
        )

    base = Feature(feature_enum[key])
    horizon = int(target_cfg.get("label_days", job_spec.label_days))
    return Ref(base, -horizon) / base - 1

```

`screen_factors.py` 现在应该成为统一初筛文件，而不是空壳或只服务某个流程。它负责：

1. 字符串表达式解析
2. 表达式结构质量检查
3. 变量/算子白名单检查
4. AST depth 检查
5. 返回标准化结果

### 建议接口

```
def parse_expression(raw_expression: str, feature_enum, operator_registry=None):
    """
    输入字符串，输出 alphagen Expression。
    解析失败不抛到外层，返回 ParseResult。
    """

```

```
def screen_expression(expr, quality_validator, dataset_meta, job_spec):
    """
    只做结构筛选，不计算 tensor。
    """

```

返回：

```
{
    "ok": bool,
    "stage": "parse" | "quality",
    "expr": expr,
    "reason": str,
    "quality": dict,
    "exception": str,
}

```

### 修改 `AlphaPoolGFN.try_new_expr()`

GFN 已经直接生成 `Expression`，所以仍然可直接进入 pool；但为了统一日志，GFN 的 `try_new_expr()` 内部仍走同样的 quality / canonical / evaluate / metrics 阶段。

### LLM / GP / PySR 的表达式必须先走 `screen_factors.py`

```
for raw_expr in generated_expressions:
    parsed = parse_expression(raw_expr, feature_enum)
    if not parsed["ok"]:
        record_candidate({
            "accepted": False,
            "stage": "parse",
            "reason": parsed["reason"],
            "raw_expression": raw_expr,
        })
        continue

    screened = screen_expression(parsed["expr"], quality_validator, dataset_meta, job_spec)
    if not screened["ok"]:
        record_candidate(...)
        continue

    pool.try_new_expr(screened["expr"])

### 8.2 GP 接入方式

建议首选 DEAP 的 GP，不要一开始自己写遗传编程。DEAP 的 GP 文档说明其树可以转为可读 Python code，并且可编译成 Python code object；其 GP 模块本身就是用来构建、评估 genetic program tree 的。([DEAP Documentation](https://deap.readthedocs.io/en/master/tutorials/advanced/gp.html?utm_source=chatgpt.com "Genetic Programming — DEAP 1.4.3 documentation"))

当前阶段只定义接口：

  max_depth: 6

输出仍是表达式字符串，不直接评估。

### 8.3 PySR 接入方式

PySR 是 Python 符号回归库，目标是寻找可解释的 symbolic expression，并且其 Python 接口背后使用 Julia 的 SymbolicRegression.jl 搜索引擎。([GitHub](https://github.com/MilesCranmer/PySR?utm_source=chatgpt.com "PySR: High-Performance Symbolic Regression in Python and Julia"))

但 PySR 更适合 tabular `X -> y`，而你这里是 panel tensor + time-series operator。当前阶段不要直接把全市场 panel 丢给 PySR。建议先做：

```

```

配置：

```
generator:
  name: pysr
  maxsize: 20
  niterations: 100
  binary_operators: ["+", "-", "*", "/"]
  unary_operators: ["log", "abs", "sqrt"]

# 10. 结论

当前最合理的工程路线不是继续扩充 GFN，也不是马上完整接 LLM/GP/PySR，而是先把项目改造成：

```
多生成器候选表达式
        ↓
统一表达式解析
        ↓
统一质量筛选
        ↓
统一数据计算
        ↓
统一指标评估
        ↓
统一日志记录

```

你现在已有的 `datahub`、`DatasetMeta`、`ParquetFeatureLoaderV2`、`AlphaPoolGFN`、`ExpressionQualityValidator`、`FactorMetricsEvaluator` 已经足够支撑这条链路；核心工程工作是**减耦合、补日志、修 target/loader 对齐、统一 import 和参数接口**，而不是新增大量目录或复杂抽象。
